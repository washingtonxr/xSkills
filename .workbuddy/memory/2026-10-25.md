- **The framing that carries the note**: a modern Wi-Fi chip is a computer running a real-time MAC, and the Linux
  driver is the north half of a distributed system whose south half is an opaque firmware binary on a Hexagon DSP.
  Everything follows from the two boundaries: the bus and the protocol.
- **Insights worth keeping**: (1) Wi-Fi 8 does **not** raise peak rate — every PHY change buys range, robustness or
  latency; a candidate who says "faster" has not read the PAR. (2) The host has no queue, so with AQL unadvertised
  the entire backlog becomes posted descriptors in hardware rings where no AQM can reach it — and the default 12 ms
  limit does not bind, so latency only responds below ~2 ms. (3) The host's airtime estimate runs ~1.85x under the
  radio's own measurement, so the limit you set is not the depth you get. (4) On a crash path, disable interrupts
  **before** freeing the data path, or NAPI polls a freed ring and takes the board down. (5) A second accelerator,
  the SoC-side NSS/ECM plane, makes flows invisible to the host — always ask which plane the traffic is in before
  concluding a QoS setting is broken.
